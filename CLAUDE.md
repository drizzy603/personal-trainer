# Fitness Programmer (repo: personal-trainer)

**The product is named "Fitness Programmer" (renamed from "Supero" on 2026-09-15).** "Supero" survives on purpose in three places and must not be swept: the Files/iCloud backup folder `Supero/` and the `supero-backup-*.json` filenames (renaming orphans every existing backup), the developer/copyright lines ("operated by Supero", "© 2026 Supero"), and Xcode target/product names (`SuperoWatch`, `SuperoWatchWidget`) plus every bundle id, the App Group and the iCloud container. A single-file web training app with an AI coach, wrapped in a Capacitor 8 iOS shell (phone app + Apple Watch app + widgets) for native distribution.

## Files
- `index.html` — the entire web app (HTML + CSS + JS in one file, including the inlined "How It Works" overlay and the inlined privacy section opened from Settings). ~15k lines, ES5-style inline JS; `render()` rebuilds `#screen`, `paintRunner()` the runner overlay.
- `build.txt` — the current `<meta build>` stamp on its own line. The native shell polls this 12-byte file to learn whether a newer page exists before downloading the whole page. `verify.sh` keeps it in sync with `index.html`; stage it with every `index.html` commit.
- `assets/fonts/` — bundled web fonts (Inter, JetBrains Mono, Anton, Archivo; latin + latin-ext woff2). `build:web` copies the folder into `www/`; every `@font-face` also carries a network fallback src so an OTA'd page on an old bundle still gets the real face.
- `sw.js` — service worker for offline/PWA support (precaches the fonts; bump `CACHE` when the list changes)
- `manifest.json` — PWA manifest (paper colours to match the default look)
- `privacy.html` — standalone privacy policy (linked from App Store; also rendered inline in Settings)
- `ios/` — Capacitor iOS shell. Custom Swift plugins live in `ios/App/CapApp-SPM/Sources/CapApp-SPM/` (auto-included by SPM; no registration beyond `SuperoViewController.capacitorDidLoad` in `ios/App/App/AppDelegate.swift`):
  - `TrovoHealthPlugin.swift` + `HealthKitReader.swift` — Apple Health: run/ride/sport import, readiness (sleep/HRV/RHR), background delivery, **and writing finished lifts as workouts when the user turns "Save lifts to Health" on**. `getState` reports the native truth for the Settings sheet.
  - `WatchSessionHub.swift` + `TrovoWatchPlugin.swift` — the bridge to the watch app (`ios/App/SuperoWatch/SuperoWatchApp.swift`): plan push, live wrist mirror, finished-session drain. **The hub owns the WCSession and is started from `AppDelegate.didFinishLaunching`** (never move activation back into the plugin: a watch message wakes the phone app in the background with no scene, so the plugin — and the web view — never load; the hub answers the watch's plan request from its cache and queues finished sessions on its own). The plugin only attaches listeners when the page is up. `clearPendingSessions({sessions})` removes exactly what the page drained.
  - `TrovoWidgetPlugin.swift` — App Group summary for the Home Screen widget (`ios/App/TrovoTimerWidget/`) and the watch complication (`ios/App/SuperoWatchWidget/`).
  - `TrovoTimerPlugin.swift` — rest-timer Live Activity. `startTimer` also forwards the rest granted so far (`total`) and the room (`theme`, from `_timerThemeTokens`); `AppDelegate` turns them into the state's `startDate` (end − total, so the bar drains like the in-app one after ±time) and `attributes.theme`. The views are `ios/App/TrovoTimerWidget/TrovoRestViews.swift` (see **Rest Live Activity** under App overview).
  - `TrovoSharePlugin.swift` + `ios/App/TrovoShareExtension/` — share-sheet image intake and iCloud backup writes.
  - `TrovoOtaPlugin.swift` — live-page staging (see Deployment).
  HealthKit entitlement is in `ios/App/App/App.entitlements`.
- **Scene lifecycle (required — never remove).** `AppDelegate.swift` holds `SceneDelegate` + `application(_:configurationForConnecting:)`, and `Info.plist` carries `UIApplicationSceneManifest` (storyboard `Main`, delegate `$(PRODUCT_MODULE_NAME).SceneDelegate`, single scene); URL opens and user activities reach Capacitor's `ApplicationDelegateProxy` and the `trovo://` deep link through the scene delegate. Without it, an app built against the iOS 26+ SDK is killed at launch on iOS 27 with `EXC_BREAKPOINT` in `___UIApplicationEvaluateRuntimeIssueForNoSceneLifecycleAdoption` — this took down TestFlight builds 44 and 45 (the first built with Xcode 27); build 46 fixed it. **The simulator does not enforce this check** — builds 44/45 launched fine on an iOS 27.0 simulator, so a simulator pass proves nothing here. Verify instead with `plutil -p <App.app>/Info.plist | grep UISceneDelegateClassName` on the archive, and on a real device.
- `release-ios.sh` — pre-archive script. Bumps the web `<meta build>` (+ `build.txt`), bumps `CURRENT_PROJECT_VERSION`, refreshes `www/`, runs `cap copy ios`. Run this before every archive. **It does not touch `MARKETING_VERSION`.** Once a version has been approved, App Store Connect closes its train — no new builds under it, not even for TestFlight ("Invalid Pre-Release Train … closed for new build submissions"). Bump `MARKETING_VERSION` in all 10 places in `project.pbxproj` (app, watch, widget and share targets must match) before archiving the first build after a release. Never run `./publish.sh` while an archive is running: it checks out `main` for a moment and swaps files under `xcodebuild`.
- `verify.sh` — static safety check. Extracts every `<script>` block and syntax-checks the combined JS, bans curly quotes in code, cross-checks inline event handlers against defined functions, fails if `index.html` changed without a `<meta build>` bump, and syncs `build.txt`. **Run before every commit that touches `index.html`** — one syntax error blanks the entire app.
- `test-native.sh` — native smoke test. Refreshes `www/`, builds the App scheme (phone + watch) for simulators, boots the paired iPhone+Watch duo, drives the main screens via `kt_dev_nav` injection, waits for the watch to pull the plan, and screenshots everything into `screenshots/out/native/`. **This is the standard flow when the user asks to "test" a change** — run it, then actually look at every screenshot. Gotchas baked in: `cap copy` alone ships a stale `www/`; forcing `-sdk iphonesimulator` breaks the embedded watch target (use `-destination`). Taps (runner sets, wrist logging) can't be driven — those behaviours live in `tests/specs/`.
- `app-store-metadata.md` — single source of truth for App Store description, App Privacy answers, and the Submission Day playbook.
- `screenshots/` — App Store screenshot pipeline. `make-seed.js` (demo data + store fixups → `out/store-seed.json`) then `shoot.py` (fresh sim container, sqlite seed injection, kt_dev_nav-driven capture of all ten 1320×2868 PNGs into `screenshots/out/`). `shoot.py` expects the sim build at `/tmp/supero-dd` (symlink your derived-data dir there). README has the full flow.
- `tests/` — Playwright regression suites (`./tests/run.sh`, ~96 specs). Headless Chromium boots index.html on the demo seed, with an optional mocked Capacitor bridge for native code paths (watch sync, widgets, OTA staging). **Run alongside verify.sh for any commit that changes app logic in `index.html`** — verify.sh catches syntax, these catch behaviour. Add a spec for every behaviour you change.

## Deployment
- GitHub repo: `drizzy603/personal-trainer`
- Live PWA at: `https://drizzy603.github.io/personal-trainer/`
- GitHub Pages serves directly from `main`, root folder — pushing deploys the web app automatically.
- **`./publish.sh` is the one way to publish.** It fast-forwards `main` to `next` and pushes, then waits for Pages to serve the new `build.txt`. It refuses anything surprising: must run from `next`, clean tree, nothing unpushed, `main` a strict ancestor of `next`, suite green (`--no-tests` skips the suite when it just ran). It never force-pushes and never touches the native shell or the App Store. Day-to-day work lands on `next`; publishing is a deliberate second step. The Claude Code permission for it lives in `.claude/settings.local.json` (`Bash(./publish.sh)`), because a hand-typed `git checkout … && git merge … && git push` compound trips the auto-mode classifier.
- Native distribution is via TestFlight/App Store; the iOS shell wraps the same web sources after `npx cap copy ios`. Archive with `-project App.xcodeproj` (there is no workspace); export with `/tmp/supero-export.plist` (`app-store-connect`, `upload`, team `7D243X2KD4`, `manageAppVersionAndBuildNumber:false`) — `/tmp` gets purged, so recreate the plist BEFORE archiving.
- **Live updates (OTA) in the native shell.** At launch the page fetches `build.txt`; only a newer stamp downloads `index.html`. On shells with `TrovoOtaPlugin` (build 41+) the page is handed to `TrovoOta.stage`, which clones the bundled web folder into `Application Support/supero-live` and writes the new `index.html` + `build.txt` there; `SuperoViewController.instanceDescriptor()` serves that folder on the next launch whenever its build beats the bundle's, wipes it once a newer binary ships, and trips a one-strike breaker (`otaAttempt`) if a served page never calls `TrovoOta.confirm()` on first render. Older shells keep the localStorage `kt_cached_html` swap (head bootstrap + `<plaintext>` hide + deferred `document.write`). Either way a change only reaches phones if `<meta build>` is strictly newer.

## Rules
- **Always commit and push after every change.** Do not wait to be asked.
- **Run `./verify.sh` before committing changes to `index.html` or `sw.js`.**
- **Bump `<meta build>` (YYYYMMDD-N, today's date) in every commit that changes `index.html`, and stage `build.txt` with it.** verify.sh enforces both.
- Curly quotes are banned inside JS — use `’` etc.
- Never commit `.DS_Store` or other system files (already in `.gitignore`).
- Keep `.gitignore` minimal. Current entries cover `.vercel`, `.DS_Store`, generated artifacts (`www/`, `node_modules/`), user-data exports (`*-backup-*.json`), and large captures (`screenshots/out/`). Don't add more without reason.

## App overview
- Four tabs: Log, Progress, Coach, Settings. Log has sub-tabs (Workout · Run · Body · + sports, user-pinnable). Unpinned, they follow the plan (`getLogTabs`): the main activity, then Run when a sport-first plan also has run days, then Body. Log › Run always renders the Run segment; a route into an unpinned tab shows it in the bar for the visit.
- All data stored in browser/WKWebView `localStorage` — no server, no accounts. Everything is **stored in lb and km**; Settings → Workout → Units switches what is shown and typed (kg / mi) through `wDisp/wStore/fmtW`, `dDisp/dStore/fmtD`, `fmtPace/paceStore`. New code must go through those helpers or it will misrender for kg/mi users.
- **Look:** two theme rooms in `THEMES` — `heavyweight` (default: paper `#f7f5ef`, blue `#0a43f5` = the action, lime `#b7f000` / ink `#4f7000` = the earned state, Anton display + Archivo body, flat white cards, fixed tab bar) and `dark` ("Lime", the original green-and-black Studio). `_paintTheme` paints tokens on `<html>` and sets `data-room`; Heavyweight's CSS is the block titled "HEAVYWEIGHT ROOM", scoped to `html[data-room="heavyweight"]`. Use tokens (`--accent` for actions, `--earned`/`--earned-ink` for earned states, `--on-accent` for text on accent, `--border`, `--card`, `--card2`); never hardcode `#000`/white-alpha colours. The week poster (always dark) takes the Studio lime via `_posterAccent()`; the watch app and its complication take the room's sat-accent through `_watchThemeTokens` (`#4d7cff` in Heavyweight, Lime's own lime); the Home Screen widget (`_widgetThemeTokens`) and the rest Live Activity (`_timerThemeTokens`) wear the room. The end-of-workout share image (`shareSessionCard`) follows the owner's room instead: `_shareCardPalette()` (Heavyweight paper/blue/lime in Anton + Archivo; Lime dark), `_shareCardModel()` is what it says (day, date, week + phase, duration, lifts/sets/RPE, volume, reps, vs last same day, every record with its gain, every lift's sets, top set and change since last time), `_paintShareCard()` draws it and steps sizes down until every lift has a row.
- **Rest Live Activity** (`TrovoRestViews.swift`, pure SwiftUI; `TrovoTimerWidget.swift` only wires it into `ActivityConfiguration`): "the poster clock". The countdown leads in the room's clock face (Anton 88 pt ink on the paper card in Heavyweight; JetBrains Mono weight 250 on the `#151517` rest card in Lime), with REST · SET n OF m / the lift / NEXT load beside it on the clock's cap line and baseline and the room's draining bar under it; the done render (end + 5 s stale) says GO in the action colour with REST DONE / NOW. The Dynamic Island repeats it on black in the satellite accent: compact = drain ring + digits, minimal (what shows while music plays) = digits only, expanded = the same row. The room rides on the activity (`attributes.theme`; else the Home Screen summary's theme; else Lime). Six static TTF faces (latin + latin-ext merged, OFL notice in each) live in `TrovoTimerWidget/Fonts`, made reproducibly from `assets/fonts` by `screenshots/live-activity/mkfonts.py` and registered by the extension's `UIAppFonts` (`Font.custom` falls back to SF silently when one is missing). Only `Text(timerInterval:)` and `ProgressView(timerInterval:)` move (`restCountdown`, `RestBar`, `RestRing`), and clock frames are computed from the faces' measured advances; a narrow card (Display Zoom, ~300 pt) steps the clock down so the column keeps ~110 pt. Preview it with `screenshots/live-activity/render.sh` (Mac) or `render-ios.sh` (iOS's own SwiftUI, run inside a booted simulator; the live bar and ring draw as placeholders there): `simctl` screenshots leave out the Dynamic Island, the simulator cannot be locked from the command line and this Xcode ships no Simulator.app. `kt_dev_nav` `runner/rest` starts a real rest (and Live Activity) in the simulator. The simulator logs `ExcUserFault_TrovoTimerWidget` XPC-misuse faults for the original build too: environmental, not a widget bug.
- Dynamic Type: `applyDynamicType()` scales the page with a root zoom (≤125%) from an `-apple-system-body` probe; Settings toggle `kt_dyn_type`.
- AI Coach uses the Anthropic API (user supplies their own key in Settings). Responses are **non-streaming** — WKWebView SSE was unreliable in the iOS PWA shell (see commit `8eea4c5`).
- **Coach models:** Claude Sonnet 5.5 (`COACH_SONNET` = `claude-sonnet-5-5`: the chat default, the Sonnet side of the Sonnet/Haiku toggle, every intake; a Sonnet 4.6/5 saved in `kt_coach_model` moves to it) or Haiku 4.5; the small one-shot calls (the morning card `fetchCoachCard`, the debrief, the sport and exercise AI fills, the key check `_pingApiKey`) use Haiku 4.5. Sonnet 5.5 requests carry the server-side fallback (`_coachFallbacks`: `fallbacks:"default"` + header `anthropic-beta: server-side-fallback-2026-07-01`), dropped for the session after a 400 that names it (`_coachNoFallback`); Haiku gets neither it nor effort. Sonnet 5.5 rules the loop must keep: no `thinking` field (adaptive; `disabled` is a 400), no forced `tool_choice` (400), and `apiMsgs` append-only within a turn with thinking blocks echoed unchanged (blocks are bound to the system prompt, tools and every earlier message — the history sent across turns is text only). Notes it writes between tool calls can come back as empty thinking blocks, so the chat prompt asks for a final reply that stands on its own; a decline (`stop_reason:'refusal'`) shows its own notice; a tool name off only in letter case runs as that tool (`_coachToolName`). The coach header's model switch reads the model's name from its id (`_coachModelName`: Sonnet 5.5 / Haiku 4.5; the version drops at ≤ 345 px so the title stays on one line) and its accessible name says which model it switches to.
- Coach supports: persistent chat history, intake flow to build a custom programme, native tool calls for routine edits (applied immediately; the newest tool message shows a PLAN CHANGES ledger with Keep / Undo = Restore Previous), image input. Programmes come from two paths: a built-in 5-tap starter intake (openStarterIntake / buildStarterRoutine — deterministic, on-device, no API key) and the Coach's AI intake for custom plans. Until one exists, the Log tab shows an empty-state CTA offering both.
- **Named slots.** A lift day's identity is one of `LIFT_TYPES` (`Push/Pull/Legs/Legs2/Arms`) — the slot: which week array it reads, how history groups, how the runner walks it. Its *name* is the user's: `kt_routine.dayNames = { Push: 'Chest + Back' }`. `_dayLabel(slot)` is the ONE read path for what to show (falls back to `SESS[slot].label`, then the id); `_dayShort` for the ~55px chips; `_slotForLabel(name, extra)` maps a name, stock label or id back to the slot; `setDayName(slot, name)` writes (stock name clears). Session records carry `label` (what the day was called when logged) — read by history row titles only, never for grouping. The watch is sent the name as `dayName` and the drain maps it back with `_slotForLabel`. The coach is told the names every turn, may set them via `dayNames` on `update_routine_weeks`, and may write a day by its name in `weekPlan` (resolved to the slot before validation). `weekPlan` never gains a new value, so an older bundled page ignores `dayNames` and still renders the right exercises. Never read `SESS[x].label` directly outside these helpers.
- Log tab reads exercises from `kt_routine` via `getSessionExercises()` / `getWkData()`. There is no silent fallback programme — but the keyless starter intake can create `kt_routine` without the AI.
- Runner: START opens a pre-session overview sheet (with the one-time REST ALERTS ask on iOS), then the deck runner (`openDeckRunner`); finishing opens the COMPLETE sheet (`openCompleteSheet`, with the one-time reminders offer). Runner state lives in `runner*` globals and a debounced `kt_runner_draft`. A workout under way (`_runnerInProgress()`: the runner open or a restored draft waiting) is never rebuilt: START, `trovo://start` and the day buttons resume it through `openDeckRunner`, another day with sets logged asks first. Log all needs a numeric target (`_logAllOk`); a record is the heaviest set with reps (`_prTop`). Working weights go through `_setWorkingWeights` (only the newest log of a lift sets one; a backdated log only raises it). A lift already in the session is not added twice. Every logged set and every Log-all has a 6 s Undo (`runnerUndoSet`, `runnerUndoLogAll`); a finished exercise offers `+1 set` (`runnerExtraSet`); RPE chips on the engaged card write per-set effort; a ledger edit survives the rest clock (`_stashRunnerEdit`); skipping the last card confirms first.
- User name is dynamic (`getUserFirstName()`: `kt_user_name` from the starter reveal's optional field or Settings, else the routine) — no hardcoded names anywhere. The coach prompt greets by that name.
- **Coach units:** prompts render every number through `fmtW/fmtD/fmtPaceStr` and open with `_coachUnitsNote()`; tool schemas carry `{W}`/`{D}` placeholders filled per request by `_unitizeSchema`; every weight-writing tool converts through `_coachLoadIn`/`wStore`, run goals through `paceStore`; `log_run` takes `distance` (user unit) or `distance_km`/`distance_mi`, programme runs accept `{mi}`.
- **Keyless proactive coach:** `_progressionDue/_plateauFixDue/_weekReviewDue` are not key-gated. Without a key, `applyProgressionLocal` / `applyPlateauFixLocal` (10% deload) write the change on-device with a 6 s Undo, `openLocalWeekReview` is a sheet, and the COMPLETE insight doubles as the Today debrief card. With a key the same taps go through the Coach.
- **Activity card** (`renderCalendar`, Progress › History): the monthly poster and the Activity Calendar in one card. The month (‹ › stop at this month, or at a later month that holds a log so a mis-dated one stays reachable: `_calLastMonth`), its active days, every day a block (workouts `--blk-lift`, runs `--blk-run`, activities `--blk-sport`, set per room in `THEMES` so the card, the day sheet and the poster read the same colours; two kinds split on the diagonal by `_calBlockBg`; rest days blank; today underlined; selection and COMPARE picks are `--text` rings), a legend, the month's volume, distance and PRs (`_monthStats`), and Share the poster (`shareMonthlyCard(mk)` shares the month on screen and stamps `kt_last_wrap` only for last month; `_drawWrapCard` draws it like the card in the room palette). The separate month poster card is gone.
- **Calendar day sheet** (`openCalDay`, `_calDayHTML`, `_syncCalDay`): Progress no longer lists every session under the Activity Calendar; tapping a logged day opens a sheet with everything on it (workouts with their lifts, runs, activities) and each one's actions (Share card, Edit sets / Edit run / Edit, Date to move it, Delete). `render()` keeps it in step (a delete stays on the day, a move follows the log, it closes when the day is empty) and repaints only when its HTML changed; ‹ › step between logged days (`_calActiveDays`); an empty day toasts "Nothing logged on …". COMPARE keeps its inline pick list (`renderCalDetail`). Progress › Runs has no run list either (the Run history list is gone): every run is a green block on the Activity card and opens from its day sheet, which reads like the old rows and like the run editor (the run's type from `_runTypeLabel`, the time through `_normRunTime` as the editor reads it, pace from the exact seconds through `fmtPace` in the owner's unit, Apple Health). Closing the sheet after a render replaced the block that opened it lands focus on the day's block.
- Compare: Activity Calendar › COMPARE picks two workouts or two runs (in memory only) and opens a then → now sheet. Same-day pairs order by start time (`_cmpT`: `startMs` on Health runs, `wristStartedAt`, `startedAt`, then id).
- Run editor: the calendar day sheet's Edit run (`#cal-edit-<id>`; focus returns to it by id after the sheet repaints) and the Run tab's saved/logged strips open `openRunEditor`. The editor, the Log › Run form (`max` + `saveInlineRun`) and the coach's `log_run` all refuse a future date. Only touched fields are validated or written, and each save has a 6 s Undo.
- **Programme engine** (`_commitRoutine`, `_progCarryLoad`, `_progSetScheme`, `_progAdd`, `_progRemove`, `_progSwap`): every write to `kt_routine` goes through one door (fresh copy, one `kt_routine_backup` per scope, a save that must succeed, then `render()`), and an edit in week c is carried into every later week keeping the programme's own climb (delta within ±25%, else ratio; deloads keep their share; weeks that keep their own reps follow by e1RM; replace-where-equal for sets/reps). Weeks stay fully written out, so every reader, the watch and older pages are unchanged. Optional marks: `row.rec` (the coach's row, kept on the owner's first edit; `rec:null` = added by the owner) and `week.recOut` (removed coach rows, restored on re-add). The runner's "Also update my programme", keyless +5, the plateau deload and `set_exercise_weight` all use it. A deload week is its own: a working weight (`o.workScale`: carry forward, +5, the plateau reset, the coach's loads) starts at the next working week, and a change to the deload week itself (Routines, the runner) stays in that week.
- **Routines** (Settings › Routines, `openRoutines`): every lift day as the coach built it; tap a lift to edit sets/reps/weight/RPE or swap it, with scope (from this week on / this week only), same-scheme or every-week reps, Climb or Hold for a row the coach held flat, and a live HOW IT CLIMBS preview; EDITED/ADDED marks with the coach's original and "Use coach's", Restore removed lifts, Add exercise, Make main, Reset day. All writes go through `_commitRoutine`, so Today, the runner, the watch, the widget, reminders and the coach follow. The read-only week ladder (`openProgrammeModal`) is "Week by week ›" inside it.
- **Coach tool calls** carry `units:{w,d}`; pills and the PLAN CHANGES rows read their numbers in those units (`_inUnitsOf`), and a unit switch drops the cached morning card. One coach reply = one undo point (`_coachTurnScope` → `_snapshotRoutineForUndo(scope)` / `_commitRoutine` scope). A document-level Escape closes the top sheet when focus has left it.
- **Coach and the owner's edits:** the owner's version wins. `update_routine_weeks` keeps rows the owner edited or added (the coach's new row becomes their `rec`) and keeps removed lifts removed, reporting `keptUserEdits`; a lift day left out of a week keeps what is stored (`[]` clears it; `_weekSchema` requires only wk/bName/bColor). `edit_programme_exercise` changes one exercise from a week on through the engine (by slot or day name; change/add/remove/swap) and makes it the programme's version. THIS WEEK'S PLAN in the prompt marks "[edited by the user; you had …]" / "[added by the user]" and adds AHEAD lines for main lifts. Carry forward (`_carryCandidates`): a lift logged a plate above the plan at the planned reps is offered once on Today and the COMPLETE sheet; one tap carries it through the engine as the owner's edit.
- **Empty lift days:** `_liftDayEmpty(slot, wk)` is the one rule. Today shows BUILD YOUR <DAY> DAY (`openBuildDay`: library suggestions for the slot and equipment, loads from `_knownLoadLb`, each week's own scheme), and the start link, coach card, week count, streak, reminders and schedule editor all treat an empty day honestly.
- **Next round** (`_nextRoundBuild`, `_applyNextRound`, `openNextRound`): the counter still parks on a programme's last week, but `kt_final_since` (the Monday the final week began; `_setWeek` and `autoAdvanceWeek` keep it) lets `_roundInfo()` tell the last week from "it ended", and Today says so (LAST WEEK / PROGRAMME DONE card). "Your next 12 weeks" (Today card, Routines row) rebuilds the same programme week for week with every weighted lift re-based on this round's best (e1RM at the lift's own reps: ~10% under it, at least a plate over this round's start, never above it) and carried through the weeks by `_progCarryLoad`; edit marks are dropped and `cycle` counts rounds. It is set for a Monday (`kt_routine_next`) and built on that morning in `autoAdvanceWeek`, or started now as this week; the old round is archived and `kt_round_intro` shows ROUND N · WEEK 1. The coach is told the last week, the end, a set round and the round number. Carry forward ignores sessions from before this round's week 1.
- PR history: Records pills and the exercise-detail PR row open RECORD HISTORY (`openPRHistory`): each record's reps and date and the records it replaced, derived from `kt_sessions` by `_prLedger()` (memoised on `_logsVersion`, never stored).
- **One streak:** `calcStreakDays()` (scheduled training days; calendar days with no plan) drives the Today chip (`… · TRAIN TODAY TO KEEP IT` when at risk), the streak milestone and the Progress hero; the widget summary carries `streakDays`.
- **Deep link:** `trovo://start` (widget `.widgetURL`) → AppDelegate parks it in UserDefaults `pendingDeepLink` and posts `.trovoDeepLink`; `SuperoViewController` evals `window._trovoOpen(url)` when the page is up; the page consumes the parked URL at boot through `TrovoWidget.consumeDeepLink` and `_handleDeepLink` opens today's session.
- Apple Watch: the phone pushes today's plan (`hasPlan:false` when there is no programme → the watch shows NoPlanView instead of "Syncing…"; Health authorization is requested at the first logged set, not at launch) (WCSession applicationContext + instant message), the wrist runner mirrors live sets to the phone, finished wrist sessions drain into `kt_sessions`. The wrist runner persists across watchOS termination and shows "Synced" only once WatchConnectivity reports delivery.

## Invariants from the 2026-10-04 hunt (126 bugs) and its regression rounds of 2026-10-06 (61) and 2026-10-09 (42, then 20; specs 103-113, 116)
- **Engine & Routines:** `week.recOut` entries are `{at, row, ss?, swap?, ssTo?}` (the superset opener a removal unpaired; the lift an owner's swap put in a week that already had it; the partner a removed opener comes back paired with, '' = none). Only the owner's removals and swaps keep anything — the coach's own (`_progRemove {coach:true}`, a swap without `markOwner`) are the programme's version. `_progDrop` removes one row (shared by remove and swap); removing the main lift hands the tag on with a `rec` mark, and such a tag-only mark (`_progTagOnly`: `rec` differs only in isMain/ss) is not an owner edit for the coach (its merge takes the coach's row; no "edited by the user" in the prompt or readback). The owner's Make main is a choice, not a tag: `_progMainOf` flags the lift that takes the tag over the coach's main (`row.mainBy='user'`, only where its coach original is not main: `_progMainMark`) and `_progMainChosen` reads the flag (a Make main from before web 20261010-1 is still read off the coach's main marked for its tag alone). The flag is ignored by `_progTagOnly`/`_progUnmark`, never copied into `rec`, kept through edits and the coach's own changes (edit_programme_exercise keeps a changed row's coach tags in `rec`; set_exercise_weight writes into a marked row's coach original, `_progCarryByName` `recFollow`), and dropped once the row loses the tag (Use coach's, Reset, a removal, another Make main) or the coach sends the row. The merge applies the coach's rows and numbers but keeps that lift main (and on the day when a rewrite leaves it out); a kept owner-edited row takes the coach's main tag otherwise, so a day keeps one main. keptUserEdits names the owner's main, the prompt says "[main lift chosen by the user]", and edit_programme_exercise `make_main:true` (asked for in the chat) is the programme's version: flags cleared, coach originals follow. Rows come back at their recorded place, last removed first (`_progAdd` back rows — loaded in weeks that never had them, 60% in deloads — Restore `_progRestoreOut` — never into a week that lacked the row — and Reset, which keeps one copy of a swapped-away lift the coach added back), then `_progSettleMain` leaves one main a day. `_progPutBack` places a returning row (Restore, an add back, Reset): an opener goes right before its partner (`ssTo`, or the owner's swap of it by `rec.name`) when that is on the day, else it comes back unpaired and the partner's entry names it (`ss`) so the pair is whole when the partner returns; a partner goes right after its opener; nothing lands between a superset's two halves. `_progSsFill` gives an entry written before 20261006-1 its `ssTo`; the coach's own swap renames `ssTo`/`ss` in recOut. `ss` names the coach's opener and `ssTo` the coach's partner by `rec.name`, never by an owner's swap of it (in `_progDrop` and the merge's re-record); a marked opener whose partner is out has its coach original say paired (`_progSsRec`, run by `_commitRoutine`), and Use coach's or Reset bring it back unpaired until the partner returns (`_progSsOut`). `_progOut` is what Restore offers; the coach's merge re-records an owner-removed lift with its swap/ss markers. `_knownLoadLb` returns a working weight: in a deload week it reads the load from that day's working week (`_progWorkWk`), so every swap/add in a deload week is loaded right; `onlyThisWeek` stops add/remove/swap at week c. `_progUseCoach` refuses (-1, toast) when the coach's lift is already on the day as another changed row. Undo of a `_commitRoutine` change drops the coach card and repaints an open Routines/Build-day sheet. Routines steppers use `_rtStepTo` (never against the press). Carry forward judges a candidate against the snapped carry (`_snapU(top.w)`); one session's carries share the undo scope `'carry:'+sessId`. ## Key localStorage keys
- `kt_sessions` — logged gym sessions (records may carry `wSet` {lift: [kept, set]}, the working weights the log wrote, and `wk0`, the week stamp a log had before it was moved into this round)
- `kt_runs` — run logs (manual + Apple Health imports; `feel` 1–5 optional; `startMs` on Health imports; `hkOrig` {date, km, time} = what Apple Health recorded, stamped on the first edit or date move of an imported run, so Reset import keeps it and it still counts as Health for the iCloud HR strip)
- `kt_sports` — non-running sport activity logs
- `kt_weights` — working weight per exercise (lb); `getWeights()` has no demo fallback (the demo loads were read as the user's and saved by the first session; a one-time boot sweep, `kt_demo_w_swept`, removes demo values for lifts never logged)
- `kt_bw` — body weight history (lb)
- `kt_prs` — cache of the current records `{name: lb}` = heads of the derived `_prLedger()` (history, reps and dates are derived, never stored); `recomputePRs`/`_syncPRCache` (boot + restore) keep it in line
- `kt_week` — current week number
- `kt_routine` — AI-generated programme (includes user name; `weeks[i].weekPlan` = per-week cadence override; `inUseFrom` = the day a programme built from nothing — the starter, the coach's first `update_routine_weeks` — was put in, carried into Programme History, backups and later rounds; `away` = the weeks it spent set aside before Restore Previous brought it back; rows may carry `mainBy:'user'`, the owner's Make main)

- `kt_apikey` — Anthropic API key
- `kt_theme` — `heavyweight` (default) or `dark`
- `kt_unit_w` / `kt_unit_d` — display units (`lb`|`kg`, `km`|`mi`); `kt_unit_regrid` — device-only note of the loads the last switch to lb moved onto lb plates `{rows:[{j,k,p,n,w:[before,after],ws?,b?}]}` (`b:1` = Restore previous programme's own moves; put-back moves prepended, at most 4000), read and written raw, never backed up, consumed by the switch back to kg

- `kt_streak_days` — the streak's lived days `{YYYY-MM-DD: 1 training | 0 nothing due | 2 optional}`, frozen before schedule rewrites (backed up; pruned to 400 days; each freeze writes the whole window); `kt_streak_seeded` — once-per-device flag for the pre-2026-10-04 seed (`_streakUpgrade`), outside backups
- `kt_wrist_closed` — device-only note of the days the phone ended a workout on `{slot: endedAt}` (6 h, raw JSON, never backed up; `_wristClosed`); `kt_ids_unique` — once-per-device flag for `_uniqueLogIds`; `kt_hk_gone` — Health tombstones for deleted runs/activities (backed up, both copies); `kt_ota_rejected` — a staged build the OTA breaker threw out; `kt_last_open` — the last visit (raw, outside backups), for the welcome-back check and `_wristLive`
- `kt_skips` — `{date,type}` skips; `_missedThisWeek()` drives the rest-day make-up CTA and `skipMissed()` records one
- `kt_dev_nav` — read once at boot, dispatches navigation, deletes itself. Used by `screenshots/shoot.py` and `test-native.sh` to drive the simulator through every screen. Routes: `log/workout` · `log/run` · `log/body` · `log/sport` · `progress` · `progress/compare` · `progress/records` · `progress/day` · `progress/calendar` · `coach` · `coach/chat` · `settings` · `modal/programme` · `modal/build` · `modal/routines` · `modal/nextround` · `overlay/how` · `overlay/privacy` · `runner/rest` (today's lift day, or the first with lifts: logs sets until a rest starts, so a real rest and its Live Activity run in the simulator; it leaves a workout under way, so a scripted run uses it last). No-op when absent. To inject without going through the in-app file picker, write the value as raw UTF-16LE into the WKWebView's `localstorage.sqlite3` (path resolves via `xcrun simctl get_app_container <phone UDID> app.kt.trainer data` → `Library/WebKit/.../LocalStorage/`; use the phone UDID — `booted` is ambiguous when the paired watch is up).

## Debugging on device
- **iOS keyboard scroll-offset guard** (boot section of index.html): after the on-screen keyboard closes, WKWebView can leave the document scrolled, shifting the paint up relative to touch targets (every tap lands below the finger). The guard snaps document scroll back to 0 on focusout/viewport-resize/scroll whenever no editable element is focused. Confirmed fixing the bug on device (2026-07-09) — do not remove; html/body are overflow:hidden so document-level scroll is always illegitimate.
- Settings → About → Error log shows `kt_err_log` and the watch-bridge breadcrumbs (`kt_wch_log`); native logs use subsystem `app.kt.trainer` (`log stream --level info`).
- A disposable diagnostics overlay for the keyboard bug existed briefly (commit `a2d1647`, removed at user request) — resurrect from git history if on-device state ever needs eyeballing again.
