Kalani Trainer
How It Works

A 12-week progressive training programme — built as a single HTML file, deployed instantly, zero accounts required.

01

Four Screens

The app has four tabs, each serving a distinct purpose in the training workflow.

🏋️

Today

Today's session — exercises, sets, reps, weight and RPE fields ready to log.

📈

Progress

Charts and PRs across all exercises. See your strength curve over 12 weeks.

📋

Programme

Full 12-week plan — every session, every exercise, every target weight.

🤖

AI Coach

Claude-powered chat that reads your actual training data to give relevant advice.

02

12-Week Training Blocks

The programme is divided into four periodisation blocks. Each has a distinct colour and training focus.

Weeks 1–4

Base

Build the foundation. Moderate loads, technique focus, establish consistency.

Weeks 5–8

Build

Progressive overload. Weights increase weekly, RPE climbs toward 8–9.

Weeks 9–11

Peak

Near-maximal effort. Heaviest loads of the cycle, high intensity.

Week 12

Deload + Test

Recovery week, then 1-rep max tests on Squat, Bench and Deadlift.

Each week has three sessions — Push, Pull, Legs — plus two runs (Tuesday 3 km / Saturday 5 km).

03

Logging a Session

Tap through each exercise on the Today screen. When you're done, the session saves automatically.

1

Open Today tab

The app shows the correct session for today — Push, Pull, or Legs — based on the current week.

2

Log each set

Enter weight, reps and RPE for each exercise. Tap the checkmark when a set is complete.

3

PRs detected automatically

If you lift more than your previous best, the app flags it as a PR in real time.

4

Finish session

Tap Complete. The session is saved to localStorage and the week advances.

5

Log your run

On run days, enter distance, time, heart rate and run type. Saved the same way.

04

Data Storage

Everything lives in your browser's localStorage — no server, no account, no sync. Export a JSON backup any time.

kt_sessions
Array of all logged gym sessions with exercises, sets, reps, weights and RPE
kt_runs
Array of run logs — distance, time, heart rate, type, date
kt_weights
Bodyweight log — date → weight (kg) entries
kt_prs
Personal records — exercise name → max weight lifted
kt_week
Current week number (1–12)
kt_bw
Most recent bodyweight entry

💾 Backup tip

Use the Export button in Settings to download a JSON file. If you ever clear your browser data or switch devices, import the file to restore everything.

05

Progress Tab

The Progress screen turns your logged data into charts — no setup required.

📊

Strength Charts

Weight over time for each exercise. See your progression week by week.

🏆

PR Board

Your all-time best weight for every exercise, updated automatically when you hit a new high.

🏃

Run Stats

Pace, time and heart rate trends across all logged runs.

⚖️

Bodyweight

Track your weight over the programme with a simple line chart.

06

AI Coach

The AI Coach tab connects to Claude (via your API key) and automatically injects your real training data into every message — so the advice is always about your actual sessions, not generic advice.

1

You type a question

Anything training-related — "Why am I stalling on squat?", "Is my RPE too high this week?"

2

App builds context

Your session history, PRs, current week and run data are bundled into the system prompt automatically.

3

Claude responds

The reply is specific to your numbers — not a generic answer. Streamed in real time.

07

Delivery & PWA

The app is a single index.html file deployed on Vercel via a GitHub push. No build step, no framework, no dependencies.

📄

Single File

All HTML, CSS and JavaScript in one file. Open it directly or serve it from anywhere.

⚡

Instant Deploy

Push to GitHub → Vercel auto-deploys in seconds. No CI, no config.

📱

Add to Home Screen

Works as a PWA. Add it to your iPhone home screen and it opens full-screen like a native app.

🔒

Offline Ready

Once loaded, it works without internet. Data stays on-device.

08

Render Loop

The app uses a minimal reactive pattern — no framework required.

1

State lives in localStorage

Sessions, runs, PRs and week number are read from localStorage on every render.

2

User action triggers save()

Any input — logging a set, completing a session — writes to localStorage immediately.

3

render() redraws the screen

The active tab re-renders from scratch using the latest state. Fast, simple, no virtual DOM.

4

WEEK_DATA drives everything

The full 12-week programme is a JavaScript object. Changing a weight or exercise only requires editing that one constant.
